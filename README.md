# MMS（MikuMikuSwim）· 深海迷航主角模型替换

**MMS = MikuMikuSwim**。用 BepInEx 插件把《深海迷航》(Subnautica) 的第一人称主角换成一个完整的 MMD 模型（初音未来等）。
不是简单挂在相机上：插件在运行时读取游戏主角的 64 根骨骼，把 **55 根骨骼（含双腿、双臂和全部手指）**
的旋转实时重定向到模型上，所以游泳、走路、手臂动作、手指动作都会跟着走。

- 版本：0.1.9
- 游戏版本：Steam 1.22.83031（Unity 2019.4.36 / Mono / 64 位）
- 插件：BepInEx 5.4.23.5，`PlayerModelReplacer.dll`（游戏日志里显示为 **MMS**）
- 模型：**不内置**。自己把 PMX 模型和贴图放进 `BepInEx\plugins\PlayerModelReplacer\Models\`

## 依赖

当前默认持物方式为 `HoldMode = VanillaAdaptive`：保留原版物品轨迹，按模型掌心校准解算手臂；肘部方向约束覆盖工具、鱼类和普通手持物。下文 `Model`、`Game` 相关段落为保留的旧模式说明。已有配置如仍为 `Model`，需手动改为 `VanillaAdaptive` 才启用新方案。

0.1.7 将双手工具的肩根去扭转处理扩展到鱼类、普通拾取物，并取消这类物品的额外肩部前伸辅助；保留 0.1.6 的缓存优化和通用肘向约束。短臂模型的极端不可达姿势仍可能出现握点间隙。

0.1.8 在求解完成后依据模型绑定坐标重建上臂轴向朝向，针对拿鱼时肩根变形、推进器上臂外侧向内旋转的问题；保留肘部和手掌的求解姿势，并将剩余扭转分配到已有的上臂扭转辅助骨。实际蒙皮效果需要在游戏中验证。

0.1.9 针对身体水平前游、推进器朝下的姿态：肘向参考增加胸前方向，手臂沿身体纵向伸出时禁止翻到背侧；肩根和瞄准骨的局部摆动限制在绑定姿势附近。掏出/切换物品时重置 IK 权重，持物手臂参与身体姿势渐变，IK 使用相同的渐变进度，避免手先到位、身体随后转动。未改动物品的原版轨迹，过渡中可能暂时存在手与握点间隙；实际动画和蒙皮效果仍需游戏内验证。

需要先安装 **BepInEx 5.4.x（x64 / Unity Mono 版）**，并确认游戏能正常生成
`BepInEx\LogOutput.log`。本包只包含插件本体，不含 BepInEx。

## 安装

1. 关闭游戏。
2. 把本压缩包里的 `BepInEx` 文件夹合并进游戏根目录，例如：
   `D:\Program Files\Steam\steamapps\common\Subnautica\BepInEx\...`
   合并后应有：

   ```
   Subnautica\BepInEx\plugins\PlayerModelReplacer\PlayerModelReplacer.dll
   Subnautica\BepInEx\plugins\PlayerModelReplacer\MMS_logo.png
   Subnautica\BepInEx\plugins\PlayerModelReplacer\Models\README.txt
   ```

3. 把模型放进 `Models\`（每个模型一个子文件夹，见下文），没有模型时模组不会替换任何东西。
4. 启动游戏。会弹出 **“MMS 使用须知”** 窗口：本模组不附带任何模型，使用任何模型前
   请先阅读并遵守该模型自带的 README 中的使用条款（署名要求、可否修改、可否商用、
   禁止事项等）。勾选 **“不再显示”** 再点 **我同意**，以后启动就直接进入游戏；
   不勾选则**每次启动都会再问一次**；点 **我拒绝** 会**直接退出游戏**。
5. 读档进入游戏，模型会在进入 `player_view` 时自动构建。
6. 进游戏后按 **F5** 循环切换 **第一人称 → 越肩第三人称 → 第二人称（正面，镜头看着角色）**。
   越肩视角里**角色的朝向不和镜头绑定**：镜头用鼠标绕角色转，角色只在移动时转向移动方向
   （不按键就保持原来的朝向），类似 MC 的越肩视角模组。**空手移动时头会跟着镜头转**（左右和
   俯仰都跟），身体仍朝移动方向；**空手停止移动满 3 秒（「待机判定延时」，可在 PDA 调）之后
   才算站着不动**，这时头和身体都不跟镜头，游戏动画里镜头驱动的扭身和镜头坐标系里的划水速度
   参数也会被抑制，所以绕角色转镜头时身体、头、头发和裙摆都不会动（手持快捷栏物品时不进入
   这个状态，身体始终跟着准心转）。松开按键后还在滑行/
   惯性前进的那些秒数，以及停下来之后的 3 秒缓冲里，头照常跟随镜头、姿势照常是活的，不会
   因为松手的一瞬间把姿势和头部跟随冻住。小键盘 **4/6** 左右、**8/2** 上下、
   **+/-** 远近、**5** 复位，实时调整镜头位置。第三人称和第二人称都能完整看到头发和身体；
   镜头就算被小键盘或地形拉得离头很近，第三人称下头部也**不会**隐藏。
   手持快捷栏物品 / 使用工具时，**身体始终朝镜头（准心）方向**，和手里的推进器/工具一致，
   站着不动时也一样；过场和交互动画（睡觉、治疗、被抓、进载具等）里朝向与第一人称完全一致。
   划水动画按**实际移动方向**播放（而不是按按了哪个键）：按 S 时角色会转身朝后游、动画仍是
   向前划水，不会出现倒着划的姿势。侧游时拿起/收起快捷栏物品，手臂会在约 0.22 秒内平滑地
   从“抓握姿势”过渡回划水姿势，不会突然抽一下。
   **水下推进器（Seaglide）**：和原版一样，身体不跟随镜头俯仰，拿在手里就横着，推不推进
   都一样；头部只按「头部俯仰跟随」做左右转头（推进器的瞄准姿势本身已经给头一个俯仰，
   再叠加会过度后仰，所以拿推进器时不加俯仰）。手持推进器时的肩部连接处不会
   折叠：手臂 IK 的伸展量改在锁骨（肩）骨上滑动，上臂和肩膀始终连在一起。
   第三人称转身不再原地硬拧：角色会先向转弯外侧带一点位移，身体同时向转弯内侧倾斜，
   像真的在水里绕弧线游过去。
   潜水镜的模拟画面只在第一人称出现；切到越肩/第二人称时会自动隐藏，回到第一人称立刻恢复。

## MMS 控制台（F2）

按 **F2** 打开 MMS 控制台（不是游戏原版的控制台），再按一次关闭：

- **MMS 总开关**：一键关闭/开启整个换模功能。关闭后立即恢复游戏原版角色，
  模型、衣服、头发/裙子物理和 PDA 预览都停止；重新开启会自动把当前模型穿回去，
  不用重启或改配置。
- **菜单键位**：默认 **V**，用来直接打开 PDA 的「模型」页。点“修改”后按下任意键即可
  重新绑定（Esc 取消），保存到配置里，下次启动仍然有效。
- **控制台键位**：默认 **F2**，同样可以在控制台里改。
- **屏蔽主角音效**：和模型页“音效”组里的开关是同一个设置。
- **打开模型页** / **重建当前模型**：不用记快捷键也能进模型页；改完配置里需要重建才生效的
  选项（比如缩放、朝向）后，可以直接在这里重建当前模型。

控制台打开时会释放鼠标；再按控制台键关闭并恢复原来的鼠标状态。
`[General] Enabled` 就是总开关的配置项，直接写 `false` 也能在启动时保持关闭。

## 换成别的模型（PDA 模型页）

本模组不附带任何模型，直接读取标准 MMD 的 `.pmx` 模型。在插件目录下建 `Models\`
（安装包里只有一份说明文件，没有模型），**每个模型一个子文件夹**：

```
BepInEx\plugins\PlayerModelReplacer\Models\
    YYB Miku\
        model.pmx          ← 文件夹里只有一个 pmx 时文件名随意
        tex\Body.png       ← 贴图路径按 PMX 里写的相对路径解析（tex/ 和 spa/ 不混用）
    sour暄\
        Black.pmx          ← 同一个文件夹里有多个 pmx 时，每个都会单独出现在列表里
        White.pmx
        tex\...
    Another Model\
        another.pmx
        textures\...
```

同一个文件夹里有两个或更多 `.pmx`（比如同一个角色的 Black / White 两个版本）时，
它们会作为**独立条目**列在模型页里，名字显示为「文件夹名 · pmx 文件名」，可以分别
预览、分别应用，隐藏/发光设置也各存一份。文件夹默认选中的那个（有 `model.pmx`
就用它，否则按文件名排序取第一个）仍然用文件夹名作为 ID，所以以前的配置和存档
不受影响；其余条目在配置里写作 `文件夹名/文件名`（如 `sour暄/White`）。

设置入口在游戏的 **PDA（平板）** 里：打开 PDA 后，顶部标签行的最后多出一个
**「模型」** 页（图标是 MMS logo；鼠标悬停提示“MMS”）。按菜单键（默认 **V**，
可在控制台或配置里改）可以直接打开 PDA 并停在这一页，再按一次 PDA 键或 Esc 关闭。

模型页分三块，界面全中文：

- **左栏 · 模型列表**：点名字只是**预加载**到预览里（列表里变成 ●，头顶显示“已穿戴”
  的是当前真正穿着的模型），确认造型满意后再点下方的 **“应用模型”** 才真正换装。
  换模型不重启、不读档，配置里会记住选择。往 `Models\` 里加了新模型后点“刷新列表”
  重新扫描（已勾选隐藏的材质列表也会跟着刷新）。
- **右上 · 3D 预览**：显示选中模型的标准 **T-pose**（模型原始静止姿势，不带动画和
  头发物理），可以直接检查造型、比例和材质。预览会铺满整个预留区域，相机会按
  当前视角自动取景，模型尽量占满画面。鼠标左键拖动旋转、滚轮缩放、
  右键拖动平移镜头；切换模型时视角会复位。预览只画模型、背景透明，
  不受墙壁和水体遮挡。
- **右下 · 部位隐藏（按材质）+ 调整**：
  - 材质列表按 PMX 顺序列出，同一行的两个勾选框：
    - **左侧勾选 = 隐藏**该部位（世界里的模型和预览同时消失），旁边括号里是贴图文件名；
    - **右侧“发光”勾选 = 让这个材质发光**，发光颜色直接取该材质自己的贴图
      （黄色发黄光、红色发红光、青色发青光）。任何模型、任何材质都能勾，
      没有默认勾选的部位。
    **隐藏和发光状态都按模型分别保存**（换模型互不影响），关掉 PDA 时写进配置。
    “全部显示”一键恢复隐藏状态（不影响发光）。
  - 调整区分成可折叠的几组，点组标题展开/收起（默认全部收起，避免一长串滑条）：
    - **头发**：头发物理、头发碰撞、四肢碰撞、第一人称显示双马尾；刘海摆动、头发刚度、
      头发重力、水的阻力、暗流强度、扭转跟随。
    - **裙子与衣服**：裙子物理、衣服物理；裙子硬度、裙摆活动范围、裙子与腿间隙。
    - **挂件**：挂件物理。
    - **水面**：水面物理；空气重力、空气阻力。
    - **视角**：头部俯仰跟随（0 = 原版骨架的效果，抬头低头时头不动；
      0.7 默认，头会跟着视角自然抬起/低下，角度分摊给脖子和头部并限制在 ±55°；
      左右转头限制在 ±60°，越过身体正后方时会平滑地绕回来，不会瞬移）；
      待机判定延时（默认 3 秒：停止移动后多久进入“站着不动”的冻结状态，0 为立即）；
      动作衔接时长（默认 0.6 秒：拿出/收起物品时模型过渡到新姿势要多久，0.1–2 秒）。
      只在第三人称/第二人称生效：第一人称下头本来就被隐藏，看不到跟随效果，
      所以保持原版，切视角时会淡入淡出；第一人称里双马尾发根的一小段
      （约 12 cm）会跟着头一起隐藏，避免转动视角时发根从画面边缘露出来。
    - **发光**：发光强度（只影响勾了“发光”的材质）。
    - **音效**：屏蔽主角音效（受伤痛呼、跳跃喘气、水下换气声）。
    各类物理开关互相独立（比如只关裙子），其他照常摆动。
    拖动即时生效，“恢复默认值”回到推荐值，关掉 PDA 时自动保存。

> 模型比例（`Scale`）、朝向（`Yaw`）、位置偏移（`OffsetX/Y/Z`）需要整模型重建，
> 所以仍然在配置文件里调，不在这个页面。

室内光照不靠手调亮度：模型和游戏原本的身体一样，会读取所在基地/潜艇的室内环境光
和生物群系光照。也可以直接改配置 `[Model] ActiveModel`，填子文件夹名
（同一文件夹里有多个 pmx 时写“文件夹名/文件名”，如 `sour暄/White`）；
留空就用 `Models\` 里找到的第一个模型，一个模型都没有时模组保持空闲，
显示游戏原版角色（不会报错）。

导入时做的事：

- 支持 PMX 2.0 / 2.1（不支持 PMD），贴图支持 png / jpg / bmp / tga / dds。
- 贴图按 PMX 里记录的原路径解析，和 MMD 一致：相对 PMX 所在文件夹（`..\` 可以跳到上层目录），
  不区分大小写；路径找不到时再按文件名找，最后按“同名不同扩展名”找（`001.tga` ↔ `001.png`）。
  BMP / TGA 的上下方向和 Unity 一致，不会出现贴图倒置。
- 骨骼按标准 MMD 日文名映射到游戏的 64 根骨骼（センター、上半身、腕.L、ひじ.L、手首.L、足.L、
  ひざ.L、足首.L 以及双手全部手指）；没有映射的骨头不会单独驱动，权重会并到最近的父骨骼上，
  静止姿势不变，所以模型外观不会被破坏。
- MMD 的手臂辅助骨会并到它们真正跟随的骨头：腕W / ひじW 这类 IK 复制骨并到上臂 / 前臂，
  ひじ補助(+)/ひじ補助1 这类肘部褶皱辅助骨并到肘；腕捩（手臂扭转）跟随上臂而不是游戏的分段扭转骨，
  避免上臂在同一段网格上被两种旋转拉扯而变形。
- 带 **M 后缀的形变复制骨**（`腕M`、`ひじM`、`手首M`，常见于 NT 系模型）也会被识别并
  并到对应的 `腕` / `ひじ` / `手首`，而不是一路折到锁骨上；这类骨骼权重很高，以前会把
  上臂靠近肩膀的一段扯变形，现在与其他模型表现一致。
- 头部与身体按“顶点主要受头部骨骼驱动”自动拆成两个网格：第一人称隐藏头部时，脸和刘海一起消失。
  骨骼名同时识别 `髪` 和 `髮` 两种写法（很多模型混用），名字里含 髪 / 髮 / hair / ツインテ /
  ponytail 的头发骨骼仍然跟着身体显示。导入模型的长发壳（双马尾）在头部隐藏时整条保留，
  只有发根贴着后脑勺的一小段（约 12 cm）跟着头部一起隐藏：第一人称镜头就在头里面，
  不藏这一小段的话转动视角时发根会从画面边缘露出来；其余马尾照常显示。
- 上臂会自动转到游戏绑定姿势相同的角度（MMD 通常是 A-pose，游戏的手臂垂得更低），
  否则手臂会比游戏动画宽出二三十度。
- 骨骼名里含 髪 / 髮 / hair / ツインテ / ponytail 等字样的链条会自动接上头发物理，
  但按部位分成三档：
  - **贴着头皮的头发**（发帽、短发层）不加物理，始终刚性跟着头骨；
  - **刘海和鬓角**（前髪 / 前髮 / もみあげ / 側髪 / 横髪 / アホ毛）只做很轻的摆动：
    整根发束作为**刚体**绕发根微微倾斜（偏离静止姿势不超过约 2 cm），不再逐关节弯曲。
    每片发丝的相对形状、发丝之间的缝隙和发片的朝向都保持模型原样，所以多根刘海不会
    卷到一起、糊成一根；幅度由 `[Physics] FringeSway` 控制，也可以在 PDA 模型页里直接拖滑条；
    `0` 时刘海和模型原始造型完全一致（不加物理、也不参与身体碰撞）；
  - **长马尾 / 双马尾 / 长发束**（长度 ≥ 30 cm）保持完整物理。
  `ネクタイ` / `Tie` / `リボン` / `マフラー` / `スカーフ` / `ストラップ` / `strap`
  这类垂挂饰品（含 YYB 10th 的 `D1..D9` 领带链）也一起摆动，开关是
  `[Physics] AccessoryPhysics`（默认开）。垂挂饰品的扭转是**由上往下带**的：贴着身体的
  最上一节最快跟上身体转动，下面每一节再依次被带着转，所以转身时领带是结带着带子甩，
  而不是像发片那样整片跟着头瞬间转过去。
  链条按 PMX 的骨骼层级自动切分：分叉处各起一条，两节就够（刘海常见的 髪 / 髪先 也能动），
  同一根骨骼不会被两套模拟同时驱动。
- **衣服**：披风、外套、斗篷这类从肩部垂下的布料（`ケープ` / `cape` / `マント` /
  `コート` / `ローブ` …）归为单独一类，按布料模拟，开关是 `[Physics] ClothesPhysics`。
  四类物理（头发、裙子、衣服、挂件）互不影响，可以单独关掉其中一类。
- **裙子**：导入模型自带的裙骨链（`スカート` / `skirt` / `裙` / `ペチコート` / `フリル`）
  也按同样的方式接进模拟，每个裙片是一条独立链；开关是 `[Physics] SkirtPhysics`（默认开）。
  裙骨不再被折叠进胯骨，所以裙边会随转身、游动摆动并回落到模型原形。
  裙片按“布料”而不是“头发”调：纵向弯曲弹簧一直保留模型原画的弧度，越到裙边越硬；
  每个关节还有一个相对原姿势的位移上限（约裙长的 32%，最多约 13 cm），突然转身、急停时
  裙边不会被甩起来翻到腰上，日常游动的幅度远在这个上限以内。
  觉得裙子太硬可以在模型页的 **裙子与衣服 → 裙子硬度** 里调低（`[Physics] SkirtStiffness`，
  默认 `1.0` 就是现在的手感；`0.7` 左右裙摆更软，`1.3` 以上更挺）。
  **硬度同时决定裙边能离开原姿势多远**：调低时弯曲弹簧变软，位移上限也会按 `1/√硬度`
  放宽（最低档约为原来的 3 倍），裙边才能被水流和大腿带着掀起来、往上折；
  调高时上限收得更紧，裙片更贴合原画、不容易翻到腰上。
  这条位移上限本身也能单独调：模型页 **裙子与衣服 → 裙摆活动范围**
  （`[Physics] SkirtLeash`，默认 `1.0`）。`0` 把裙片钉在原姿势，裙摆仍会跟着胯骨整体转动，
  但完全不再滞后、不会被掀起来；`2`–`3` 允许裙边离开原姿势更远，转身、急停和暗流里能翻得更开。
  它是在硬度换算之后再乘上去的，所以两者会叠加；想要“很挺但绝不翻起来”就把硬度调高、
  活动范围调低。
  向前跑动时大腿会在两帧之间扫过好几厘米，裙片来不及跟上，所以碰撞除了检查每根裙骨，
  还会在每段裙片的中段补采样，并让腿部碰撞体按大腿的实际移动速度临时外扩（最多 4 cm）：
  膝盖不会从裙摆的缝隙里顶出来。裙片在同一帧里做三轮“推开 → 保持段长”，最后再单独推一次，
  避免最后的段长修正又把裙片拉回大腿里。
- **水面**：`[Physics] SurfacePhysics`（默认开）把水上和水下分开处理。露出水面的
  头发和裙摆按**干布**算：受 `[Physics] AirGravity`（默认 6 m/s²）向下拉，只有
  `[Physics] AirDamping`（默认 3.0/s）的空气阻力，也没有暗流；泡在水里的部分保持
  接近失重、高阻力的湿布手感。交界处有 5 cm 的过渡带，裙边扫过水面时不会突然变硬。
  站在基地、逃生舱或载具里时整个人都在空气中，按干发处理。关掉这个开关就回到
  全部按水下计算的老行为。
  **头发在空气里有额外的重量**：干发部分的重力是 `AirGravity × 1.8`、阻力是
  `AirDamping × 2.6`（裙子和挂件不受这个倍率影响）。上岸后马尾会像有重量一样
  直接垂下来，大约一次摆动内停住，而不是从发根到发梢来回晃好几下；在水里仍是原来的
  湿发手感。老配置里 `AirDamping = 1.2` 的会在启动时自动升级到 3.0 一次，之后可以
  在模型页的 **水面 → 空气重力/空气阻力** 里按手感微调（这个倍率会一起缩放）。
- 物理开启时，模拟的发束、饰品和裙片会与**从模型自身网格量出来的身体体积**碰撞：
  每根身体骨（头、脖、胸口、上/下躯干、锁骨、上臂、前臂、手掌、大腿、小腿、脚踝、脚掌）
  沿高度方向拟合一叠 6 个椭圆截面（不是一颗包住整根骨的大椭球——那样髋部的表面会落在
  碰撞体外面 2–4 cm，裙子就能陷进屁股），跟着动画骨骼一起转，所以侧游、转身、弯腰时
  屁股和胸也会把布料顶开，抬手划水时马尾不会从抬起的胳膊里穿过去。
  碰撞作用在**布料表面**而不是骨骼线：布料网格相对骨骼线的平均偏移和厚度都会先量出来，
  领带的前片会贴着胸口被推回、马尾不会被弹离身体半个头。可在 `[Physics] HairCollision` 关掉。
  **四肢碰撞**另有独立开关 `[Physics] LimbCollision`（默认开，模型页“头发”组里的
  “四肢碰撞”）：关掉后只保留头、脖和躯干碰撞，手臂和腿不再推开布料，适合模型四肢
  贴得特别近、或想省一点 CPU 时使用。手指骨太细，不参与碰撞。
  裙片和衣服只和腿（大腿、小腿、脚踝、脚掌）碰撞，不和手臂/手掌碰撞：手在待机姿势下
  本来就垂在裙子两侧的腿边，若让手参与，游泳划臂时裙片会被手推出去、又被大腿推回来，
  两侧来回打架会抖；发束和挂件仍然和手臂碰撞。
  `[Physics] SkirtClearance`（默认 2 cm）是裙子与腿之间保证的最小间隙，量出的布料厚度
  不够时由它兜底。腿还是常穿模就调大（最大 8 cm，太大会显得裙子被撑开）。
- 模型按 PMX 原始比例缩放对齐（×0.08 再乘 `[Model] Scale`），比例差别很大的模型可以调 `Scale`、
  `OffsetX/Y/Z` 微调。

| `[Debug] ShowcaseDistance` | `0` | **仅调试用**：把模型推到镜头前方若干米，方便观察模型；正常游戏请保持 `0`，否则看起来会像第三人称 |

物理配置项在 PDA 模型页里拖动即时生效；模型比例、按键、可见性等其余配置项
仍需重启游戏（材质和网格在模型首次载入时构建）。
换模型和隐藏部位都不用重启：按菜单键（默认 **V**）打开 PDA 模型页即可；往 `Models\` 里加新模型后，
点“刷新列表”重新扫描。

**怎么调：**

1. 关闭游戏，用文本编辑器打开 `BepInEx\config\com.miku.subnautica.playerreplacer.cfg`；
2. 改对应的一行（例如 `HighlightGlow = 1.0`），保存；
3. 启动游戏并读档，新值立即生效。

想先看清效果，可以按 **F5** 切到第三人称，再游到光线暗一点的地方——不发光的部分会融进黑暗，
高光会明显亮着。改坏了就删掉整个 cfg，下次启动会按默认值重新生成。

常见的两处手感：

- 头发太“弹”或太“飘”：加大 `HairDamping`（12–16），或减小 `HairStiffness`（3–4）。
- 头发太死、像塑料条：减小 `HairDamping`（6–8），或加大 `HairStiffness`（7–10）。
- 高光不够亮：加大 `HighlightGlow`（1.5–2）；觉得整张脸都发亮就减到 0.5 或直接 0。
- 室内/洞穴里角色偏暗：模型已经通过 `SkyApplier` 读取基地/潜艇的室内环境光和所在水域的生物群系光照，
  和游戏原本的身体一致；如果还是觉得暗，可以稍微加大 `EmissionFill`（0.15–0.2），代价是高光会更亮。
- 刘海/鬓角摆得太多或太少：拖 PDA 模型页里的“刘海摆动”，默认 `0.35`。

> 如果你之前装过旧版本，`HairStiffness` 的含义已经改成“弯曲刚度”、`HairFlow` 的单位也变了，
> 建议删掉旧的 `com.miku.subnautica.playerreplacer.cfg` 让它按新默认值重新生成。

## 实现要点

- 插件通过 **Harmony** 补丁挂在 `Player.LateUpdate` 上，绕开 BepInEx 管理器对象在主菜单场景加载时被销毁的问题。
- 从 `player_view` 下的潜水服 SkinnedMeshRenderer 收集 64 根骨骼的绑定姿势，把每根骨骼的旋转增量
  表示在**蒙皮网格空间**（`delta = inverse(smrRot) * sourceRot * inverse(bindRot)`），再叠加到
  挂在 `player_view` 下的模型容器上。这样身体随视角左右转向时模型也会跟着转（早期版本用世界空间
  增量，会把整体朝向抵消掉，导致模型朝向固定）。
- 模型骨骼与游戏骨骼同名（`hips`、`spine_1`、`hand_L_thumb_base` …），共 55 对，手指全部覆盖。
- 游戏自带的 `player_view` Animator 默认是 `CullUpdateTransforms`，隐藏潜水服模型后它就不再更新骨骼，
  所以插件启动时把 `Animator.cullingMode` 设为 `AlwaysAnimate`，保证游泳/跑步等动画继续驱动骨骼。
- 每一帧把模型头骨锁定到游戏头骨位置，保证相机始终在头部内；随后隐藏头部网格。
- 重定向**跑两遍**：一遍在 `Player.LateUpdate` 之后，另一遍在 `LateUpdate` 的最末尾
  （`DefaultExecutionOrder(32000)`）。因为游戏用 RootMotion FinalIK 摆第一人称手臂，
  IK 求解器在自己的 `LateUpdate` 里写手骨——比 `Player.LateUpdate` 更晚。如果只更新一次，
  模型用的就是上一帧的手臂姿势，而挂在游戏手骨上的手持物品用的是这一帧的，
  一低头抬头物品就会从手里“滑出去”（实测每帧差 1.7–3.2 cm）。
- **以模型为准的持物（`HoldMode = Model`，默认）——后拉 + 位置 IK**：
  - 掏出/收起阶段工具完全保持原版姿势（权重 0），所以凝滞枪/重力枪的掏出动画不会被插件改坏；
  - 收起动作结束约 0.45 s 后，工具沿角色朝向**向后拉** `ItemPull` 米（默认 6 cm），把握把拉近，
    弥补模型手臂比潜水服短的问题；
  - 然后 `HoldArmIk` 用**位置-only 两骨 IK**把左右手分别解算到后拉后的掌心点（双手工具两只手都解算），
    改的只有上臂/前臂的朝向和肘部，手骨旋转、手指、锁骨都不动，所以不会拉扯手指或把上臂折进身体；
  - 后拉权重只在稳定持物时淡入，收起时立即归零，工具原姿势恢复。
  早期试过“搬工具进掌心”“构建时拟合臂长 + 掌心对齐”“物品平移/双手倾斜”，分别造成过穿胸、
  手指被拉长或掏出动画被破坏；这版把“后拉”限制在稳定持物阶段，并且只解算手臂位置。
- **两骨 IK 只在 `HoldMode = Game`（以及 PDA）时运行**，保留作为对照和退路。旧版描述如下：
- 手部用**两骨 IK**，所有尺寸都以模型自身的比例为准：上臂、前臂长度每帧直接从模型骨架量
  （YYB 模型约 0.230 + 0.212 m，明显比游戏潜水服的手臂短），掌心长度也取模型手腕到中指根
  的距离；目标位置、滑动上限和各项容差全部由这些测量值按比例推出，不从潜水服骨架取尺寸。
  游戏的手骨只提供目标姿势。插件每帧重定向完旋转后，先算出肘部要弯的角度、重新瞄准上臂，
  再把前臂转到指向目标。手骨用**掌面对掌面**的标定：构建时分别用两套骨架自己的
  腕→中指根→拇指根算出掌心坐标系（手指朝前、拇指一侧为上），存下把游戏手骨朝向映射到
  模型手骨朝向的常量旋转；每帧把手骨设成「游戏手骨朝向 × 这个常量」。模型的手心、指根和
  拇指方向因此都和游戏潜水服的手套手一致，握把落在掌心里，左右手用同一套规则。
  早期几种做法都握不住：直接沿用重定向的腕部滚转（滚转在潜水服的绑定坐标系里）掌心相对
  握把歪约 90°；从模型绑定姿势重建手骨则翻到另一侧；只对齐腕部方向、不标定滚转同样偏。
  一旦手骨被钉住，**前臂的滚转从手骨重建，上臂滚转保留重定向**：构建时记下模型绑定姿势里
  手骨相对前臂的局部旋转（`WristLocal`）；每帧先得到最终手骨朝向（「游戏手骨朝向 × 掌面标定」），
  前臂 = 手骨朝向 × `WristLocal` 的逆，再朝肘部 IK 目标做最小弧度瞄准；上臂只朝肩→肘方向
  做最小弧度瞄准，滚转不动。上臂滚转是锁骨、肩垫和袖口一起继承的；把它也从手骨重建，
  会把整套绑定坐标系的滚转差推到**手臂根部**，拿水下推进器/海蛾号时根部明显拧转。
  上臂保留重定向滚转后，剩余的那部分滚转差交给模型自带的 MMD **扭转骨组**：
  「腕捩」（`arm_twist_*`）夹在上臂与肘之间，「腕捩1/2/3」是它的兄弟骨，
  通过 PMX 的继承旋转分别复制 25/50/75%。插件每帧按上臂轴向量出肘部还需要多少扭转，
  把全部角度写到 `arm_twist_*`、按比例写到三根辅助骨上，于是袖子从上臂到肘部**逐渐**扭转，
  而不是在肘关节处拧成一坨；IK 松开时这组骨的局部旋转复位，不会把扭转留在袖子上。
  早期几种做法都把误差堆在一个关节上：前臂沿用重定向的滚转（在潜水服的绑定坐标系里），
  手却被钉在游戏手骨上，两者最多差四分之一圈，手腕只能**折起来**补偿；只从手骨反推前臂，
  肘部又会吸收全部差异而**拧成一坨**；按住 W 时游戏给手部加旋前，滚转分配错了，
  两条手臂还会**向外翻**。现在手腕跟随手骨、上臂根部和袖口跟随重定向，中间的差异由
  扭转骨组分担。锁骨链（MMD 的「肩」→「肩C」→「腕」，
  其中「肩C」接游戏的 AimIK 抬肩骨）也从绑定姿势重建：只保留游戏抬肩给出的**方向**，
  滚转回到模型自己的绑定轴向，否则拿水下推进器时（抬肩骨转到约 80°）手臂根部会拧转。
  早期版本直接把手掌瞬移到游戏手骨上，前臂被硬拉长，双手握持和划水时就会看到手部严重变形。
- 手臂够不到目标（划水、把物品举到最远）时，整条手臂会朝目标**刚性滑动**，上限为模型
  自身臂长（上臂 + 前臂）的 20%（YYB 模型约 8.8 cm）；比例固定，换模型时补偿量随模型缩放。
  滑动发生在**锁骨（`clav_L` / `clav_R`，MMD 的「肩」骨）**上而不是上臂（`shoulder_*`，MMD 的「腕」）：
  以前把上臂从肩骨上挪开会撕开肩关节，拿水下推进器时肩膀和手臂连接处会折叠；
  锁骨根藏在肩垫和躯干里，滑动时上臂、肘、手一起移动，肩关节始终连着。滑动量每帧在求解前复位，
  不会累积；IK 淡入淡出时滑动的也是锁骨，过渡中不会再次脱开。
- IK 的**修正量按 0.22 s 淡入淡出**（0..1 权重，在纯重定向姿势和完全求解姿势之间插值）。
  以前拿起/收起物品时 IK 在一帧内开关，侧游中收起物品手臂会突然从抓握姿势弹回划水姿势；
  现在两个方向都是平滑过渡，权重为 0 时才完全跳过求解。
- **旧版：让物品适配模型（`MoveHeldItemToModelHand`，只在 `HoldMode = Game` 时作为附加开关）**：工具挂在
  游戏插槽上按游戏原本的动画运动，手臂用上面的 IK 贴上去（会弯肘、滑锁骨、扭袖子来够到
  游戏手骨）。如果目标是“模型一点不走样”，打开这一项就反过来：持物时**完全不跑手臂 IK**，
  模型手臂保持纯重定向的原版姿势（YYB 比例、滚转都不动），每帧把手持工具搬到模型右手掌里。
  工具的父节点仍是游戏的工具插槽（`QuickSlots` 用 `ModelPlug.PlugIntoSocket` 挂到
  `Inventory.toolSocket`），插件记下插槽原始的局部变换，用动画中的父骨骼重建出游戏原本的
  世界姿势，再乘上「游戏 `hand_R` → 模型 `hand_R`（经 `PalmFix` 掌面标定）」的刚体偏移：
  工具保持它在游戏手里时的握持关系，只是换了一只手骨做基准。偏移每帧从原始基准重算，
  不会累积；工具属性（碰撞、物理、射线）都不动，只改渲染变换。日志 `Item adapt:` 会打出
  插槽路径、插槽是否在 `hand_R` 之下、偏移距离/角度以及两只手骨的距离，用来确认适配是否正确。
  PDA 不是快捷栏物品，始终用 IK。
- **旧版：保持原版持物动作（`HoldPoseMode`，仅 `HoldMode = Game`）**：持物时手臂只做纯重定向——不求解 IK、不采集
  姿势、不瞄准，模型保持自己的比例和肘部形状，工具留在游戏作者的插槽里。重定向本身已经把手的
  **朝向**做对了，差的是**位置**：重定向的身体骨架从不跟随视线俯仰（俯仰只存在于相机和游戏的
  第一人称手臂装备 `ArmsController` 上），而工具插槽挂在那套手臂下，所以低头抬头时模型手掌和
  工具会错开几厘米。这几厘米不再修正，原因见下一条。
- **为什么放弃瞄准修正（`HoldAim`，默认关）**：要把掌心想放到工具上，必须同时满足四个条件——
  手的位置、手的朝向、模型自己的骨长、自然的腕——而它们互相矛盾。腕一旦保持自然，前臂方向就被
  手的朝向唯一确定，肘的位置随之确定，肩也必须正好落在离肘 `l1` 的地方；第一人称手臂是按它自己
  的比例排的，和模型的骨长对不上（模型臂长实测 0.462 m，够到工具要求手臂折到 0.34~0.47 m，
  比伸直短 3~13 cm），所以这组条件无解。解算器只剩「肘在圆上的角度」一个自由度，差值只能全部
  压到腕上：日志实测重定向自己的腕角 `wrist0=3~48°`，瞄准解算后 `wrist=63~125°`，腕多折
  60~100°，画面里就是手腕扭了、掌心朝下。为了跟随俯仰，上臂还要转 30~61°、锁骨 19~25°，肩根
  的变形就是这部分旋转本身，不是蒙皮错误。默认关掉之后，手臂、腕、肩、袖口都回到原版动画。
- **旧版：两骨瞄准解算（`HoldAim` 打开时才跑，仅 `HoldMode = Game`）**：分三段——**锁骨先转一部分 → 上臂转到解算出的肘 →
  前臂转到原版手**，手骨的世界朝向在解算后原样恢复，让腕去吸收前臂改方向带来的差值。肘落在
  “两骨都能勾到目标”的圆上，弯折方向优先取**手骨当前朝向下、腕保持自然时的前臂方向**
  （`rest.MidDir` × 手骨世界朝向），这样腕补的角度最小；重定向的手臂接近伸直时那个方向是噪声
  （左手肘反折就是这个），便退回重定向的肘，再退回“朝下、略朝外”（`HoldPole`）。锁骨承担所需
  摆角的 **35%**（上限 25°）以减轻肩根折痕；剩下的比例差沿瞄准方向平移锁骨，上限臂长的 20%；
  摆角和平移每帧在求解前重建，不会累积。整条修正按 0.22 s 权重淡入淡出（`_aimWeightL/R`）。
  日志 `Aim R/L:` 里 `wrist0` 是解算前的腕角、`wrist` 是解算后的腕角（两者之差就是这条修正的
  代价），`swing`/`clav` 是上臂和锁骨各自的转角，`bend` 是解算后的肘角，`gap`/`slide` 是比例
  缺口和实际滑肩量，`handErr` 是模型手到原版手的距离。
- **手骨的朝向已经是对的，不要再修它**：日志里的 `handDiff` 是「原版第一人称手骨朝向」与
  「身体潜水服手骨朝向」的夹角，运行时一直是 **0**。所以任何“腕的局部修正”都是错的：潜水服
  绑定的腕相对肘是 **179.2°**（T 姿势掌心朝下），把它当成腕的 delta 写回去，就会把掌心翻成
  朝下——这是之前几次修改看起来“没变化/更糟”的原因。
  之前试过的几种“腕部校正”都不能写：掌面标定（`PalmFix`）的帧由拇指根/中指根位置搭出来，
  模型手骨绑定坐标系和潜水服不一致时会算出 150° 以上（YYB 上 168°/145°）；腕关节局部增量
  （`L0⁻¹·L`）也不行——日志里 `bind wrist` 是 **179.2°**，潜水服的绑定腕关节和肘几乎反向
  （T-pose 掌心朝下），把这个绑定帧带过来，掌心就朝下了、手腕被拧几十度。这两条都只在构建时
  打日志，运行时不参与姿势。
  日志 `Pitch R/L:` 会打出原版手骨是否找到、原版手相对相机的俯仰（`vPitch`）、模型手到原版手的
  距离（`handGap`）和当前权重（`aimW`）；`Aim R/L:` 每 2 秒（左右各自计时）打出上臂和锁骨
  各自转过的角度（`swing` / `clav`）、解算后的肘角（`bend`）、比例缺口和滑肩量（`gap` / `slide`）、
  手部残差（`handErr`）、腕关节角（`wrist`）、弯折方向在“下 / 外”方向上的分量
  （`poleDown` / `poleOut`），以及 `handDiff`。`poleDown` 应为正、`poleOut` 小正数；
  `poleDown` 为负就说明肘朝上/朝后折了。
- **动作切换的姿势衔接（姿势交叉淡化）**：拿起/收起快捷栏物品、进出过场时，游戏是一帧之内
  把动画状态换掉的，重定向会把这个跳变换到模型上，看起来就是整个身体“啪”地换了个姿势
  （水下推进器最明显）。检测到持物/过场状态变化、或者源骨架（网格空间，排除整体转身）
  单帧有**至少两根躯干/上臂骨**转动超过 60° 时，重定向会在 `[View] PoseTransition`
  秒内（默认 0.6，PDA「动作衔接时长」可拖 0.1–2）做姿势交叉淡化：**从切换瞬间模型显示的
  姿势**平滑插值到实时重定向出来的新姿势，曲线是 smoothstep（两头慢、中间快），父骨先转、
  子骨跟随，躯干、肩膀和头一起过渡，最后几帧自然收住，不会像早期版本那样到后半段突然
  “甩”过去。两个 LateUpdate 通道都用同一份起始姿势插值，同一帧跑两遍也不会加速。
  起始姿势取的是**叠加头部视角跟随之前**的重定向基础姿势（`ApplyHeadLook` 是每帧往脖子/头上
  再乘一份视角旋转，如果拍快照时把这份也算进去，淡化期间就会叠两次，切换瞬间头会多转十几度
  再慢慢消掉——拿/收物品时“头抬一下”就是这个）；手臂 IK 是绝对覆盖并在淡化后重新求解，
  所以基础姿势里不含 IK 也没问题。IK 自己的 0.22 s 权重淡入淡出继续把手臂送进/送出抓握姿势。
  **没握东西的那只手不参与交叉淡化**：单手持物时物品挂在右手，左手一直在播游戏原本的动画，
  如果把它也拉回切换瞬间的旧姿势，拿/收物品的 0.6 s 里这只手就会“卡住”再慢慢追上（用户报告的
  “另一只手卡顿”）。现在握持手以外的整条手臂（`clav_*` / `shoulder_*` / `elbow_*` / `hand_*`
  及其手指）直接用实时重定向姿势，完整还原原版动作；双手握持（如海蛾号/水下推进器）和过场时
  两只手仍按原逻辑一起淡化，握持那条手臂本来就由 IK 绝对覆盖，不受淡化影响。
  日志里会打 `Pose transition: held=… cinematic=… freeArm=L|R|none` / `Pose jump: 骨骼 角度, 骨数`，
  方便确认是哪条路径触发的。
  检测器**按票判断**：只有至少两根近端骨（骨盆、脊柱、锁骨、上臂、肘）同时超过 60° 才算切换，
  脚趾/手指/手/腿/眼睛等远端骨不投票——划水时这些骨单帧就能转过 35–60°，早期“任意一根骨
  超过 35° 就触发”会把正常动画帧当成切换，每次触发都从**上一次**的姿势重新开始 0.6 s 淡化，
  模型一直被拉回旧姿势，表现就是有些动作时快时慢、甚至像慢动作。正在淡化时和触发后 1 s 内
  也不会再次触发，淡化不会被反复重置。
- **导入模型的裙子**：PMX 自带的裙骨链直接作为模拟链使用（10th 模型是 7 层 × 18 个扇区的
  裙骨阵列），蒙皮权重不用改；每个裙片最靠腰的那一节只按模拟结果的一半转动，
  另一半保持绑定姿势，避免摆动时把裙腰从腰上“撕”开、露出接缝。
- **布料模拟**用 Verlet 粒子：每个关节记住上一帧位置，速度直接由位移得到（因此天然带惯性），
  每帧再叠加几乎为零的向下加速度（湿发接近中性浮力）和一股很慢的行波：越靠近发梢、越晚被推动，
  于是头发会像水草一样从根到梢逐段荡漾，站着不动时也在飘。
- **水的阻力是各向异性的**：每帧把关节速度拆成沿发丝和垂直发丝两部分，垂直方向阻尼强得多。
  头发是一束细纤维，侧向划水时受阻远大于顺着长度滑动，这样马尾才会被水流带着“顺”在后面，
  而不是像橡皮筋一样整体弹回。
- **形状保持用的是逐节弯曲刚度**，不是把关节拉回原始位置：每一节都朝着“上一节按模型原始
  曲率转过一个角度后”的方向转回去（角度在头部坐标系里定义），转回量按 `1-exp(-stiffness·dt)`
  取，并且越靠发梢保留的原始弯曲越少（发根 100% → 发梢 55%）。这样阻力会沿发丝累积：
  发根保留造型，发梢顺着水流拉直，整条马尾能弯成平滑的弧线。早期版本把每个关节用弹簧拉回
  它在头部空间里的绝对静止位置，整根头发会被弹成一个刚体——“面筋”；改成整条链的形状匹配后
  又会把模型的扇形轮廓整体转过去，游泳时像硬翅膀。逐节弯曲没有这两个问题。
- 发梢**不会被约束“重新点燃”**：弯曲和长度约束是直接把关节挪到新位置的，如果把这一帧的
  修正量全部当成速度带进下一帧，轻飘飘的发梢就会以接近帧率的频率来回振（看起来像在抖）。
  所以速度只保留（阻尼 + 重力 + 暗流）积分出来的部分，约束修正只带走 25%，越靠发梢越少（到 4%），
  再叠加越靠发梢越弱的弯曲刚度（×0.6），发梢才会像湿发一样拖着漂，而不是抽鞭子。
- 骨骼朝向以**绑定时的姿势**为基准：`b.rotation = (LookRotation(当前段方向, 参考上方向) ×
  LookRotation(静止段方向, 静止参考方向)⁻¹) × 绑定旋转`。早期版本用当前头部朝向做基准并把结果
  再乘回头部朝向，等于把“玩家累计转过的角度”直接变成了绕发丝长轴的滚转——马尾几乎垂直悬挂，
  绕竖直轴转就是绕自身长轴滚，所以转身/移动时扁发片会一直打转。数值验证：头部偏航 90° 而发链
  不动时，旧公式让每片发带拧转 88.8°，新公式为 0.0°。
- 滚转参考方向沿链条**平行传递**：根节取绑定参考，并且用根骨从绑定到当前的旋转把它带过来
  （和根节的瞄准方向一样），之后每一节都用“上一段→当前段”的最小旋转把参考方向带过去，再投影
  到当前段的垂直平面。根节的参考方向如果留在世界空间，垂直悬挂的领带/裙片转身时滚转就不跟身体，
  看起来会像朝反方向甩；带上根骨旋转后整条链是无扭转的，发片只随空间摆动、不绕自身
  轴旋转；而且当马尾被水流冲成“朝上”（与静止方向接近 180°，下潜时很常见）时也连续——旧的
  最小弧公式在那个位置轴会乱跳，单帧骨骼旋转可达 152°，发梢会疯狂翻面；平行传递下同场景最大
  只有 5.7°/帧。
- 静止曲率（逐节弯曲）仍以头部坐标系表达，由 `HairTwistFollow` 控制其跟随身体的滞后，让转身时
  马尾的造型柔和地甩过去，而不是每帧复制头部动画的抖动。
  模拟只跑在 `LateUpdate` 的最后一趟（本帧最终姿势之后）；玩家瞬移时（单帧位移超过 1 m）
  粒子直接重置回原始姿势，避免布料被甩飞；单个关节每帧位移还被限制在 12 cm 以内
  （60 fps 下相当于 7 m/s），防止硬转向后的甩鞭把发丝抽飞。
- 三轮长度约束保证骨段长度不变。
- **越肩 / 三人称视角**（F5 循环 第一人称 → 越肩第三人称 → 第二人称）：只移动 `Camera` 这一个
  transform——相机在每帧所有相机更新之后才被移动，相机座架、第一人称手臂、手持物品都不动，
  所以重定向和 IK 完全不受影响；切回第一人称时把相机原来的本地变换还回去。越肩视角沿视线方向
  后退、抬高并向侧面偏移（`ThirdPersonSide`，默认右肩），角色因此落在画面一侧；第二人称沿同一条
  视线走到角色前方，再转过来看着角色的脸（镜头方向、视线的偏航/俯仰都取自相机自己的朝向，不拿
  玩家根节点当朝向，所以站在地上和游泳时都对得上）。两条路径都用 SphereCast 做碰撞，遇到地形或
  基地会把相机拉近。模式切换先淡出到第一人称再淡入新模式，不会从身后“瞬移”到身前。进载具、打开
  PDA 时自动回到第一人称。头部隐藏的距离判定（默认 0.75 m）**只在第一人称生效**：第三人称/第二
  人称下即使镜头被拉得很近也照常显示头部，只有切回第一人称、镜头重新进到头部里时才隐藏。
- **越肩视角的朝向解耦**：游戏的骨架本来会跟着视线转，所以镜头没法绕角色转。插件在重定向时把
  模型容器的**世界朝向**单独写出来——模型转不转只由 `PlayerController.velocity` 的水平方向决定
  （低于 0.4 m/s 时保持上一帧朝向），镜头再转也不会带着身体走。只转模型这一层，游戏自己的
  玩家朝向、移动输入、瞄准和碰撞体都不变。进出视角、拿起/放下快捷栏物品时朝向用 0.2 s 淡入
  淡出，不会突然甩身；手持物品时**始终**跟回镜头方向（站着不动也一样），让身体和 IK 的手
  与物品对齐（推进器指哪，身体就朝哪）；空手原地不动时保持朝向（否则绕镜头转会把整个角色
  和头发一起带着转）。小键盘的偏移写在 `[View] ThirdPersonSide/Height/Distance` 里，松键时保存。
- **头部朝向**：空手移动时身体仍朝移动方向，插件在重定向之后把脖子和头按 35% / 65% 的比例
  转向视线方向（左右限制 ±60°，俯仰 ±55°）。手持物品时照常叠加俯仰，**只有水下推进器例外**：
  它的瞄准姿势已经让头跟着镜头俯仰，再叠加会让头过度后仰。这个附加转向和俯仰共用 `HeadLook`
  比例，并在**空手原地不动**或**播放过场/交互动画**时缓动淡出到 0，所以空手站着只转镜头时头不会动。
  淡出是带缓动的（smoothstep，0.8 s）而不是直接归零：停下之后头会自己慢慢转回朝前的待机姿势，
  不会“啪”地弹回去；重新开始移动时用 0.3 s 淡入回跟随。实际施加的角度本身还按 0.1 s 的时间常数
  做指数平滑，所以视线越过身体正后方时头是绕回来的，不是瞬间跳到另一侧。
- **原地转镜头不再扭动身体**：游戏的 `ArmsController` 每帧把摄像机的偏航角速度
  （`view_turn`）和俯仰（`view_pitch`）写进玩家 Animator，重定向会把这个骨架姿势复制到模型上，
  所以站着不动只转镜头，脊柱也会扭、头发和裙摆跟着摆。插件在 `SetPlayerSpeedParameters`
  之后把这些参数归零，适用于第三人称下**空手、没有移动输入、并且停止移动已超过待机延时**
  的状态和“过场/交互动画”。手持快捷栏物品时**不**抑制：游戏就是用这两个参数把身体转向
  准心的，压掉之后躯干留在原地、而瞄准 IK 仍把手按在镜头上，只有手臂跟着转，抓着东西的
  小臂还会被拧到胸前（看起来像小臂内外翻过来）。除了两个视角参数，还压掉
  `move_speed` / `move_speed_x/y/z`：水里待机时浮力、暗流和待机浮动让速度不为零，而这组参数
  是按镜头坐标系拆分的（`GetRelativeVelocity()` 用 `camRoot`），绕镜头一转它的分量就跟着变，
  动画于是带着身体晃——头已经被单独冻住了，看起来就是“头不动、身体物理还在甩”。待机延时
  （`[View] IdleDelay`，默认 3 秒）就是给这段缓冲用的：刚停下来时姿势还是活的，停稳之后才冻结。
  手持物品时不进入这个冻结状态：推进器/工具要始终指向准心，身体就得继续跟着镜头转
  （见上文“身体始终朝镜头方向”）。冻结时这几个参数在 0.55 s 内缓动压到 0、恢复移动时 0.25 s 淡回来，
  所以进入/离开待机不会抽搐；模型本身的朝向、倾斜和位移仍由上面的速度逻辑驱动。
- **待机时绕镜头不再带着模型平移**：模型整体贴到游戏骨架的头部位置（`_container.position +=
  源头部世界坐标 − 模型头部世界坐标`），用来保证头和骨架始终对齐。但越肩视角只解耦了模型的
  **朝向**，游戏自己的骨架仍然跟着视线转，而头部骨骼离骨架原点有 0.1–0.3 m 的横向偏移，
  于是鼠标一转账，源头部世界坐标就绕原点画一个小圈，整个模型被拖着平移，世界空间模拟的
  头发/领带/裙子跟不上就甩起来——陆地空气阻尼小所以最明显，水里也看得出来。现在越肩视角下
  这个锚点改用**模型自己的朝向**重建（骨架原点 + 模型朝向 × 头部局部偏移，再按朝向解耦权重
  过渡），绕镜头时模型原地不动，只有真正的移动和姿势变化才会带动锚点；第一人称仍然是原来的
  头部对齐（眼睛必须在模型头里）。
- **越肩视角的转身手感**：水下玩家的 `PlayerController.velocity` 来自刚体，方向**每 50 Hz
  物理步**才更新一次；直接用它当作模型朝向目标，渲染帧率高于 50 时模型就会一顿一顿地转。
  插件把水平速度方向按约 70 ms 的时间常数做平滑（速度低于 0.3 m/s 不跟随、低于 0.12 m/s
  退出，带迟滞，避免缓慢漂移时原地乱转），再按 80 ms 收敛、上限 900°/s 跟随，于是任何帧率下
  转身都是连续的。转身同时带**位移感**：插件按模型朝向实际变化的角速度算出一个 -1..1 的
  倾斜量，给模型容器加最多 14° 的滚转（向转弯内侧压），并把整个身体向转弯外侧平移最多
  12 cm（头部锚点不动，像上半身拐过去、下半身还带着旧方向），松开后随角速度一起回落。
  移动时划水动画完全交给游戏：插件不写 `move_speed_*`、也不在模型骨骼上叠加转身动作
  （只有待机冻结时才会把这些参数压到 0，见上一条）。
- **越肩视角的划水方向**：游戏的划水动画参数（`move_speed_z` 等）是 `ArmsController` 用
  `camRoot.GetAimingTransform()`（就是主相机）把速度拆到相机坐标里得到的。朝向解耦以后，按 S
  时角色会转身朝镜头游，但动画仍按“相机后退”算，划水看起来是反的。插件只在
  `ArmsController.Update` 执行期间临时把相机的**朝向**换成“相机与模型朝向按淡入系数插值”的
  方向（俯仰保持不变），更新完立刻还原，于是动画始终按角色实际前进的方向播放；位置、移动输入
  和移动逻辑都不碰，W/S/A/D 仍然相对镜头移动。手持物品（朝向已跟回镜头）时不替换。
- **第二人称的方向**：镜头被转过来看着角色，但游戏的前进方向取自相机——直接用翻转后的相机会让
  W/S 反着走、游泳动画也朝后游。插件在玩家的地面/水下移动和手臂动画更新期间，临时把相机本地方向
  换回翻转前的朝向，更新完立刻还回去；角色因此始终朝着自己的正面走，划水动作和原版一致。
- 贴图由 PNG 在运行时用 `Texture2D.LoadImage` 加载。材质**克隆游戏自己的潜水服材质**
  （MarmosetUBER）再逐项设置属性，所以能接入游戏的阳光/环境光/雾效；游戏构建里剥掉了
  Unity Standard 的自发光变体，用 Standard 会导致背光面纯黑。
- 动态物体的光照由游戏的 `SkyApplier` 提供：它把当前生物群系或玩家所在基地/潜艇的
  `interiorSky` 写进每个渲染器的材质属性块（环境球谐、IBL 曝光等）。插件给模型容器加上
  一个 `SkyApplier` 并监听 `SkyEnvironmentChanged`，所以进出基地、切换水域时模型会和游戏
  原本的身体一样跟着变亮变暗，而不是只吃全局环境光（那在室内几乎是黑的）。
- 为了让深水阴影里也保留颜色，`EmissionFill` 把反照率贴图的一部分接到材质的辉光通道
  （`_EnableGlow` + `_Illum` + `_GlowColor`），本质是廉价的补光，不是真实光照。
- **高光发光**沿用同一条通道，但不是按亮度自动挑像素，而是按**材质**：在模型页勾了
  “发光”的材质额外乘一个放大系数，别的材质不碰。发光直接取该材质的反照率，所以颜色不会被改掉：黄色发黄光、红色发红光、
  青色发青光；同一张贴图里的暗部因为反照率本身就低，也不会亮。`_Illum` 直接指向反照率贴图，
  亮度写在 `_GlowStrength`（= `EmissionFill + HighlightGlow`，可大于 1），着色器里两者相乘，
  效果和早期“把整张 4K 贴图复制一份、按系数缩放后烘焙成辉光贴图”完全一样，但不再为每个材质
  多占一份显存、也不再多做一次全图 CPU 缩放和上传。
  另外 `EmissionFill` 给**所有**材质（含头发和皮肤）叠一层很弱的自发光，全身保留一点微光；
  它之前一直没生效，所以默认值从 0.5 降到 0.12，避免通道打通后把颜色冲淡。
- 关键的一行开关：MarmosetUBER **只有在材质启用 `MARMO_EMISSION` 关键字时才会采样
  `_Illum`**，而游戏潜水服材质默认没开。插件克隆材质后会显式 `EnableKeyword("MARMO_EMISSION")`，
  否则整条发光通道（补光和高光都算）会被静默忽略。启动日志里会打一行
  `Glow setup: _Illum present, MARMO_EMISSION was off, ...` 方便排查。
- 模型自带的 `No01`（手臂“01”贴片）贴图是**只有 alpha 通道有形状**、RGB 全部为红色的贴图；
  直接当反照率会渲染成一个红色方块。插件把它当**镂空贴片**渲染：打开 `MARMO_ALPHA_CLIP`、
  `_EnableCutOff = 1`、`_Cutoff = 0.35`，透明像素直接裁掉，只留下“01”字形。早期版本把 alpha
  压平、和写死的肤色 `(250, 226, 222)` 合成一张不透明贴图，肤色对不上模型手臂的明暗，
  看起来就是一块贴纸贴在手上。
- 第一人称隐藏头部用 `ShadowCastingMode.ShadowsOnly`：网格不渲染但**仍然投射阴影**。

### 换模型的速度与显存

- 每个模型第一次被选中时解析并转换 PMX，转换结果留在内存里；再切回同一个模型只做一次
  顶点/权重数组的深拷贝，不再重新解析。构建过程会就地改写顶点数组，所以缓存始终保留原始数据。
- 启动时就用 Unity 的原生图片解码器在后台线程预解码当前模型的 PNG/JPG 贴图，进游戏构建
  模型时直接取用，不再在主线程里同步解码；PDA 里点模型时同样先后台解码，解码完成后才生成
  预览。等待期间页面上保持**上一张预览**不动（不会闪回穿戴模型；页面第一次打开、还没有任何
  预览时显示“正在加载模型…”），新预览就绪后在同一帧里换上去。第一次预览一个从未解析过的
  模型时，PMX 解析也放到后台线程，避免点一下卡一下。BMP/TGA 仍走同步解码（Unity 的图片
  解码器不支持这两种格式）。
- 点“应用模型”时，预览已经创建好的材质、透明度分类结果和贴图会直接交给穿戴模型使用，
  不再重复创建材质和重新扫描贴图 alpha；同一模型的透明度分类结果也会缓存，切回来不再重算。
- 每帧构建/预览的耗时写进 BepInEx 日志（`Miku player model attached (... ms)`、
  `Preview built ... in N ms`），想确认卡顿来源时可以在日志里看。
- 切换时先销毁旧模型的容器、`SkinnedMesh` 网格、材质、解码出来的贴图，以及构建预览时
  派生出来的贴图，再构建新模型。早期版本只清空贴图字典，每切一次就泄漏一整个模型的显存
  （导入模型动辄几百 MB），表现为越切越卡、切几次后崩溃。
- 发光不再为每个材质复制整张 4K 贴图（那是切换卡顿和显存峰值的主要来源）：每个材质少一份
  与反照率同样大的纹理上传，切换时的纹理传输量大约减半。
- 模型页和控制台的中文字体在插件启动时就创建好并预生成字形（13 / 15 / 16 / 17 / 20 五个字号），
  第一次打开 PDA 模型页不会再卡顿。
- PDA 标签页注册全部走 Harmony 且逐项容错：`SetTabs` 只在游戏传入自己的普通标签列表时
  临时插入自定义页（调用结束立刻移除），所以普通 PDA 键仍打开上次的普通页、游戏自己的
  本地化检查也不会去查不存在的 “Tab8”。页面在 `uGUI_PDA.Initialize` 之后建好并登记；
  任何一步失败都会把工具栏恢复成原样，不会留下索引不到的标签。
- 实时预览用一台**关闭自动渲染**的相机手动 `Render()` 到与预览框同比例的 RenderTexture
  （高度 720，宽度按预留区域的实际宽高比生成，所以画面不会缩成中间一个小方块）：
  渲染前把模型渲染器临时换到空闲层 31、强制打开阴影（第一人称下头部是 `ShadowsOnly`）、
  临时关闭雾并打开一盏只照 31 层的补光，渲染完在 `finally` 里全部还原，
  所以主视角画面完全不受影响。
- 预览内容是**静态 T-pose**，所以只在需要时重绘：换模型、旋转/缩放/平移视角、
  切换隐藏或发光后才渲染一次，之后一直复用这张 RT，不再每帧渲染。
  “应用模型”后如果预览仍显示穿戴模型（模型无法单独构建时），才退回每帧渲染。
  PDA 关闭后不再渲染，页面销毁时一并释放 RT、相机和灯。
- 点另一个模型时**不再立刻销毁旧预览**：旧预览先留在屏幕上（等待期间连它的视角复位也不重绘），
  等新模型的贴图解码完、新副本在后台线程解析完成后，才在同一个 `Update` 里释放旧预览并构建新的，
  紧接着的 `LateUpdate` 就画出新预览，中间没有任何一帧会退回“穿戴模型 + 当前动作姿势”。
  点回正在显示的那个模型会取消还在进行的加载。

## 已知限制

- 第一人称下相机就在模型头部里，低头时会看到自己的胸口/手臂；按 **F5** 可以切到越肩第三人称或第二人称看清全身。
  越肩视角里空手时角色只在移动时转身，站着不动用鼠标环视时角色会保持原来的朝向（只有头
  转过来看镜头）；手持物品时（包括站着不动）角色始终跟着镜头方向，所以那种状态下仍然会
  “镜头转到哪、角色转到哪”。
- 第三人称下镜头贴着头部（小键盘把距离拉到最近，或被地形/基地挤到角色身后）时，头部仍然
  显示，不会消失；这时镜头可能贴进头发或头部网格，看到一些近裁剪面切开的截面属于正常现象。
- 旧版 `HoldMode = Model`（以模型为准）：掏出/收起时工具保持原版姿势，动画不被破坏；
  稳定持物后工具后拉 `ItemPull`（默认 6 cm），再用 `HoldArmIk` 只解算双臂位置到后拉后的握把。
  手骨、手指、锁骨不动，所以不会拉手指或折上臂；后拉/解算权重只在稳定持物时生效。
  如果觉得工具离镜头太近，调小 `ItemPull`；想完全不后拉/不解算就设 `ItemPull = 0` 或
  `HoldArmIk = false`。
- MMD 模型与游戏角色的身材比例略有差别，手骨位置已经对齐、手指也会跟着游戏手指弯曲，
  但模型手掌的厚度和游戏手套不同，个别握把上仍会有轻微的穿插（属于模型本身的差异）。
- 头发/裙摆是简化的布料：每根马尾 8 个关节、每片裙摆 3 个关节，身体碰撞体是按身体骨
  拟合的椭圆截面叠层，现在覆盖头、脖、躯干和四肢（锁骨、上臂、前臂、手掌、大腿、
  小腿、脚踝、脚掌）。四肢碰撞可以在模型页“头发 → 四肢碰撞”或 `[Physics] LimbCollision`
  单独关掉；手指骨太细，没有碰撞体，所以发丝仍可能从指缝间穿过。
  裙片和衣服只与腿碰撞，不理会手臂和手掌，免得手垂在裙边时把裙片推得来回抖。
  胳膊挥动很快时，单帧内扫过的距离仍可能让布料短暂穿插一瞬，调整 `HairStiffness`
  可以让它更“硬”从而减少穿插。
- 只在进入游戏、角色骨骼可用时构建一次；换存档/重载场景后会自动重建。
- 游戏内载具、过场等状态下可能不显示模型，属正常现象；此时模型页预览会显示
  “模型在当前视角不可见”，正在构建模型时显示“正在加载模型…”。
- 手柄可以在标签行切到「模型」页；页面里的勾选、滑条和列表面向鼠标 + 键盘
  （游戏在使用手柄时会主动关闭 PDA 的射线输入）。
- 逐材质隐藏是按“材质名”隐藏，同名材质的所有子网格会一起消失（例如同一张贴图
  分成多个子网格的部位）。隐藏不重算包围盒，所以预览取景不会跳。

## 卸载

删除 `Subnautica\BepInEx\plugins\PlayerModelReplacer\` 整个文件夹即可。

## 从源码重新构建

源码在项目 `src/PlayerModelReplacer/`（`PlayerModelReplacer.cs`、`PmxModel.cs`、`PdaModelTab.cs`、`MmsConsole.cs`、`ConsentGate.cs`），构建脚本：

```bash
bash tools/build_plugin.sh
```

脚本使用 Unity 2019.4 自带的 Mono + csc，引用游戏目录下的 `Assembly-CSharp.dll`、`UnityEngine.*.dll`
以及 BepInEx 的 `BepInEx.dll` / `0Harmony.dll`。
