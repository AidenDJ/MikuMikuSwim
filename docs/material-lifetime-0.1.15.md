# 0.1.15：PDA 模型切换后的透明与发光材质

本次读取到的 0.1.14 游戏日志显示：首次构建使用 `MarmosetUBER`；随后在 PDA 预览并应用 42summer、Skadi、YYB Miku 时，材质出现 `_ALPHATEST_ON`、`_ALPHABLEND_ON`、`_EMISSION` 等 Standard 关键字，而原版材质使用 `MARMO_ALPHA_CLIP`、`MARMO_ALPHA`、`MARMO_EMISSION`。应用时记录为 0 ms 材质处理，说明备用预览材质直接被沿用，未重新验证其着色器。YYB 身体和头部的渲染层日志均为 8，没有据此改动渲染层。

原有实现保存原版 Renderer 的材质引用，后续预览依赖这个引用仍然有效；同时 EnsureMaterials 在发现已有材质时立即返回。此次修正这个生命周期和校验缺口：

- 从原版 Renderer 的全部材质槽寻找 MarmosetUBER，创建独立模板并保留，避免后续预览依赖原版材质实例的寿命。模板不参与普通模型切换时的材质销毁，宿主最终清理时释放。
- 预览构建前尝试补齐模板；应用时再次验证预览捐赠的材质。如果用户启用原版材质且模板可用，备用或缺失材质会用原版模板重建，继续复用已解码贴图和透明分类结果。
- 用模型宿主的父子关系排除本模组 Renderer，不仅依赖模型命名，覆盖原名不是 Miku_ 开头的导入模型和颈部封口。
- 透明材质诊断日志增加实际 shader 名称，便于下一次游戏内确认。

保持原有透明分类阈值、混合设置与用户保存的发光选择。颈部封口仍使用自己的不透明材质，不改变原模型材质。

验证：使用安装游戏的程序集构建通过，保留四个原有未使用字段警告；检查材质创建、预览捐赠、替换模型排除和清理路径。没有启动或操作游戏；不同模型反复切换后的实际透明、发光和材质生命周期仍待游戏内验证。
