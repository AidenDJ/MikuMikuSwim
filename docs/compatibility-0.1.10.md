# 0.1.10 兼容性、掏出过渡与性能

## 两个模型的修正

sour White 的袖口挂在 `手W/ひじW` 辅助链下。旧导入器只检查当前骨骼的替代目标，走父级时会越过这些辅助骨，把右侧袖口归到肩部。现在沿父级查找时也保留辅助骨对应的肢体归属，`手W` 作为前臂辅助处理，不把整个袖口旋转直接绑定到手腕。

HCMiku 马尾的末端有重合的 IK 控制骨。旧实现将其加入物理链，末端长度为零后拒绝整条链。现在导入时区分 IK 控制骨与变形骨，并在构建物理链时合并重合节点，保留有效发链。

实际 PMX 转换对比：

| 检查 | 修改前 | 修改后 |
| --- | --- | --- |
| HCMiku 有效长马尾链 | 0 | 2 |
| sour White 右袖口主权重 | 277 个顶点跟随 `clav_R` | 277 个顶点跟随 `elbow_R` |
| sour White 左袖口主权重 | 跟随中间辅助骨 | 277 个顶点跟随 `elbow_L` |

## 掏出物品

仅在掏出/切换的身体姿势渐变期间，为物品计算与模型右掌一致的共同过渡变换；双手目标使用同一个变换，物品内部的原生握点不重复转换。手沿这个物品目标求解，肩部修正继续随身体渐变淡入。结束时变换归零，接回原版物品轨迹。

每帧早期恢复上一帧临时局部变换，防止累加偏移；如果游戏已写入新局部姿势或改变父节点，则保留游戏的结果。模型销毁、切换模式和禁用时也会清理临时偏移。

## 性能

- PMX 网格转换不再为每个顶点创建两个四元素数组，改为每个网格复用一组临时空间。
- 头发、裙子和挂件的固定绑定朝向及根旋转逆矩阵在创建物理链时缓存。每帧仍计算实时目标朝向，保留物理步长与关节数量。
- 物理全部关闭时跳过水面及碰撞体采样；没有启用碰撞路径时跳过身体碰撞体更新。
- IK 的骨骼/物品缓存和空手快速返回继续保留。

编译结果检查确认 `SimulateCloth` 中的 `LookRotation` 调用位置由 2 处减少为 1 处，`Inverse` 由 3 处减少为 1 处。移除的计算已移至创建物理链时执行，具体每帧节省量取决于链条和骨骼数量。

## 验证与边界

使用生产 PMX 读取/转换代码，对本地 23 个已安装模型执行离线转换及输出权重归一化检查，全部通过。对 HCMiku 的两条有效马尾、sour White 的右袖口归属另有断言。独立数学检查覆盖 10,000 组共同变换及旋转缓存等价性。

可复测一个 PMX：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test_model_compatibility.ps1 -ModelPath "完整模型路径\White.pmx"
```

此工具只读取模型数据，不运行游戏、不修改 PMX。需要本机 Unity 2019.4 Mono 和游戏程序集，路径可通过参数覆盖。

以上检查不能代替实际头发摆动、袖口蒙皮和掏出动画的画面验证。游戏由用户启动和操作；未测量或承诺具体 FPS 提升。短臂模型的极端不可达姿势仍可能留有握点间隙。
